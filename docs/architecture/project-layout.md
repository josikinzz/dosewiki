# Project Layout

Last verified: 2026-04-23

This is the quick map for contributors deciding where code belongs. Keep it focused on folder ownership and repository hygiene; deeper runtime details live in [Runtime and Data Architecture](runtime-and-data.md), and operational guidance lives in [Operations and Direction](operations-and-direction.md).

## Active Code Areas

```text
src/app/        Next.js App Router routes, layouts, metadata routes, and API handlers
src/features/   Feature-owned UI and editor workflows
src/components/ Shared presentation components and UI primitives
src/data/       Local artifacts, content builders, static config, generated schema helpers
src/hooks/      Client hooks for editor, search, config, and data flows
src/schema/     Canonical Zod schemas
src/styles/     Global CSS partials imported by src/styles.css
src/utils/      Routing, SEO, tag, slug, and interaction helpers

lib/            Shared server/runtime helpers used outside the client feature tree
convex/         Convex schema, queries, mutations, and generated Convex API bindings
scripts/        Local operational scripts for migration, generation, parsing, and audits
```

App Router APIs live in `src/app/api/`. Reusable server-side helpers for those routes live in `lib/server/`; do not reintroduce tracked code under the retired root `api/` directory.

## Operational and Generated Code

- `scripts/batch/`, `scripts/parsers/`, `scripts/migrate/`, and `scripts/convex/` are operational tooling, not public runtime code.
- `src/schema/substance/contract.ts` is the shared substance article contract adapter used before Convex article ingestion and by contract tests.
- `src/data/schema/` contains generated and config-heavy schema helper code; update it through the schema generator when the source schema changes.
- `convex/_generated/` is generated by Convex and should not be hand-edited.
- `cleanup/` records cleanup plans and execution history; it is not part of runtime behavior.

## Ignored Local Artifacts

The following paths are local generated output or machine noise and can be removed safely:

- `.next/`
- `.generated/`
- `dist/`
- `dist-inline/`
- `coverage/`
- `public/share/`
- `tmp/`
- `.DS_Store`
- `.codex-dev.log`
- `.codex-dev.pid`

Use:

```bash
npm run hygiene:check
npm run hygiene:clean
```

The approved cleanup policy is declared in `scripts/lib/local-artifact-hygiene-policy.mjs`; update that module and this list together when artifact hygiene rules change.

`hygiene:clean` intentionally preserves secrets, dependencies, editor settings, Vercel state, archives, quotes, and tracked planning docs. It does not delete `.env*`, `node_modules/`, `.vercel/`, `.vscode/`, `.claude/`, `archive/`, `quotes/`, or tracked `notes-and-plans/` files.
