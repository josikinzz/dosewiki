01 · Operating model

Production is canonical.

Local JSON, Markdown, reports, and plans are evidence or migration inputs. They do not override newer live records.

!
Every configured Convex target is production.

The repository invariant points local, preview, and production work at prod:glad-minnow-656. Effect Index remains read-only.

Inspect

Read the live row, schema, current artist, storage IDs, and recent ledger.

Gather evidence

Keep sources, hashes, frame sheets, and ambiguity notes outside the live row.

Freeze a plan

Use stable IDs, slug checks, expected snapshots, and explicit operations.

Apply with guards

Use the exact target, confirmation phrase, scoped credential, and digest.

Verify live

Re-read every changed row, relation, URL, and route. Record a ledger.

Read these first

  1. AGENTS.md for repository invariants.
  2. CONTEXT.md for canonical replication language.
  3. docs/agents/convex-credentials.md before a write.
  4. docs/agents/deployment.md before a function deploy.
  5. The target script and its tests before execution.

Do not trust these without refresh

  • Counts in old reports or commit messages.
  • Exported artist names or effect sets.
  • Resolved storage URLs. They can expire.
  • A dry-run plan after another agent edits production.
  • Filename similarity as proof of duplicate identity.
02 · Record anatomy

One row carries five kinds of truth.

The schema separates identity, classification, delivery, chronology, and rights. Keep those concepts separate during edits.

Media type

image, video, and audio are valid. Animated GIFs remain image rows.

URL resolution

Native Convex storage wins. Direct row URLs are fallbacks. Preview URLs have no direct fallback.

Audio exception

Legacy effect audio can also live in subjectiveEffects.audio_replications. Audit both surfaces.

04 · Write boundary

A production write needs four locks.

The shared command ignores browser compatibility URLs. A privileged write must name its exact target.

shared production ceremony
TARGET_CONVEX_URL=https://glad-minnow-656.convex.cloud \
node scripts/replications/<guarded-script>.mjs \
  --write \
  --confirm-write=<operation-name> \
  --expected-deployment=glad-minnow-656 \
  <operation-specific-confirmation>
i
Never deploy Convex functions with a bare CLI command.

Use npm run convex:deploy -- --prod --from-head-worktree --confirm. The wrapper protects concurrent local work and live-only functions.

Required batch properties

  • Immutable row IDs with slug cross-checks.
  • Full expected snapshots for compare-and-set writes.
  • Atomic, resumable ledger checkpoints.
  • Exact target and source hashes.
  • Post-write reads for every planned outcome.

Conflict policy

  • Stop when a live row differs from the frozen plan.
  • Do not weaken the expected snapshot.
  • Rebase the plan from the current live row.
  • Review the changed operation again.
  • Resume only with the matching digest and target.
05 · Media pipeline

Preserve masters. Publish renditions.

Replication media is the subject matter. Compression, framing, duration, audio, and source completeness affect meaning.

Still-image comparison

  • Use cryptographic hashes for exact files.
  • Use pHash, dHash, crops, and color features for candidates.
  • Compare native detail, crop, watermark, and provenance.

Video comparison

  • Compare duration and container metadata first.
  • Use spread-out frame sequences.
  • Check audio streams and full sequence completeness.

Keeper decision

  • Prefer the most complete defensible source.
  • Keep higher effective detail, not dimensions alone.
  • Record the rejected twin and reason.
Video delivery contract

Use H.264 with yuv420p and +faststart. Keep audited masters outside the delivery copy. Preview renditions are muted, short, and capped at 480px.

Storage rules

Store Convex storage IDs on rows. Resolve URLs during reads. Direct URLs remain fallbacks. A foreign storage ID can silently serve the wrong fallback media.

Deletion rules

Deleting a database row does not authorize storage deletion. Keep media objects unless the user explicitly includes them and a recovery path exists.

i
Candidate evidence is not an apply manifest.

Contact sheets and fuzzy clusters identify review targets. They do not authorize deletion, archival, or credit changes.

06 · Classification

Effects and substances are different relations.

An effect describes what appears in a work. A substance showcase records an editorial association for one article.

Effect ownership and tags

  • effect_slug is the primary owner.
  • effect_tags holds additional depicted effects.
  • Validate every planned effect slug.
  • Preserve confirmed audio tags during exact visual edits.
  • Use the current live set as the edit baseline.

Substance showcase curation

  • curated_slugs controls inclusion and order.
  • removed_slugs records explicit suppression.
  • The two arrays must not overlap.
  • Use expectedUpdatedAt to protect concurrent edits.
  • A replicationPlaylist is only a named, ordered set of eligible slugs. Applying one edits a gallery draft; substanceGalleries remains the publish gate.
  • Playlist saves also use optimistic concurrency and prune deleted or corpus-retired slugs.
  • Verify the public substance query after the write.
!
Do not derive substance truth from filenames alone.

A title can provide a candidate association. The final gallery pairing is an explicit editorial decision.

07 · Attribution and chronology

Uncertainty stays visible.

Credit and date research need evidence. Unknown identity is safer than a plausible but unsupported attribution.

Artist identity

  • Use exact, normalized aliases only when evidence supports them.
  • Keep row-specific misattributions separate from global name corrections.
  • Update credit lines and rightsholders with the artist plan.
  • Never merge artists because their styles look similar.
  • Preserve source URLs and research notes.

Date research

  • State whether the date covers creation, publication, export, or source post.
  • Use exact date, year, range, upper bound, inferred, or unknown.
  • Record confidence and limitations.
  • Keep rejected and alternative dates.
  • Hash the source artifact and source record.
i
Production still contains legacy Unknown and Anonymous artist strings.

The domain term is Unattributed. Do not collapse or rename those rows without a reviewed migration plan.

09 · Completion gate

“The mutation passed” is not completion.

Verification must cover the database relation, stored media, resolved response, and public route affected by the operation.

Database

  • Exact changed row snapshots.
  • Unchanged row count unless planned.
  • No forbidden artist-wide tags.
  • Complete ledger keys.

Media and API

  • Storage ID resolves.
  • Thumbnail and preview resolve.
  • Duration, format, and audio match.
  • Public query returns the intended row.

Public surface

  • Permalink returns the intended media.
  • Artist and effect focus views agree.
  • Substance showcase includes or excludes it.
  • Renamed routes redirect correctly.
