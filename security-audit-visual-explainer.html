Database integrity & developer-tool security

No open back door. Too much blast radius.

The current code does a good job preventing an anonymous visitor from directly writing to Convex. The more serious problem is what happens after one trusted credential, editor session, workstation, or adjacent service is compromised: the system can publish false safety information immediately.

Bottom line: keep the existing authentication foundation, then add containment—separate draft from publication, require independent approval, make revisions immutable, and remove remote JavaScript from the admin origin.

The risk in one picture

How false information could reach the public site

This is not proof that an attack occurred. It shows the shortest credible path after one trusted boundary is lost.

1 · EntryTrusted boundary is compromised

Remote analytics host, legacy admin password, editor session, scoped token, master key, or local workstation.

→
2 · ValidationThe document has a valid shape

Zod and route guards correctly reject malformed or unauthorized writes—but they cannot judge factual truth.

→
3 · DatabaseThe live row is replaced

No required expected revision, separate approver, or immutable audit event at the main publish boundary.

→
4 · PublicCaches purge; false text renders safely

React escaping prevents injected HTML. It does not prevent convincing but incorrect dosage or harm-reduction claims.

The design goal should be: one compromised person or component can propose a change, but cannot silently publish, erase the audit trail, and prevent rollback.

Controls already working

  • All 49 public Convex mutations call an auth helper.
  • Seven destructive functions are internal.
  • The `/dev` UI has middleware and server-page gates.
  • Public article data uses deliberate projections and schema validation.
  • Production diagnostics default closed.

Containment still missing

  • No independent draft → review → publish boundary.
  • No required compare-and-swap revision on article saves.
  • No immutable, complete audit event for every publish.
  • No tested first-class rollback and cache-purge workflow.
  • Too many systems can fall back to a universal master key.

Detailed review

The four high risks

These deserve owner assignment and explicit verification, not merely a code patch.

Remote script on the admin origin

SEC-01
Worktree remediated · not deployed

A compromise of the analytics deployment or DNS becomes an authenticated admin-browser compromise.

The shared root layout loads analytics.dose.wiki/script.js on the admin host. Its domain-filter option controls tracking, not execution.

src/app/layout.tsx:17–23, 72–87
Live admin HTML confirmed the script.
Fix first: omit it entirely from admin and previews; then add a nonce-based CSP.

Legacy password equals admin

SEC-02

One exposed password creates an admin session with no app-level login throttle or second factor.

The provider is permitted in production and active on the live host. JWT sessions have no short, explicit admin lifetime or immediate revocation boundary.

auth.ts:31–63, 84–93
src/lib/auth/roles.ts:5–20
src/app/api/auth/[...nextauth]/route.ts:1–6
Fix first: disable it outside local use or make it normally-off break-glass; use MFA-capable identity and distributed throttling.

Save means publish

SEC-03

A stolen editor session can publish false content and mark it reviewed without a second person.

The main save replaces the live article and clears caches. It does not require the revision the editor began from, and audit data is not complete and immutable.

src/app/api/save-to-convex/route.ts:250–256, 337–377
convex/lib/substanceIngestion.ts:195–226
convex/changelog.ts:40–89
Fix first: immutable revisions, expected revision, separate author/approver, published pointer, append-only events, tested rollback.

Citation safeguards stop at the client

SEC-04

A scoped citation token can submit broad prose changes that look evidence-backed.

The database mutation validates the general article structure but does not independently prove that only citation markers and matching evidence changed.

convex/citationEvidence.ts:87–115, 602–627
scripts/citations/apply-workbench-draft.mjs:52, 119
Fix first: compare marker-stripped prose in Convex, require expected revision, validate evidence correspondence, and separate proposal from promotion.

Medium and low risks

Open any row for the practical impact and the recommended control.

SEC-05MediumEditor/raw Convex queries are anonymous
Impact: middleware hides the page, not the Convex API. Raw articles, editor review metadata, prompts, quotes, sources, and templates can be scraped. Fix: leave only minimal public projections anonymous; protect editor reads with Convex identity, a Next server boundary, or internal queries. Evidence: convex/substanceIndex.ts:20–123, convex/prompts.ts:16–34, convex/quotes.ts:20–115.
SEC-06MediumBroad Convex key is the fallback for narrow writes
Impact: one key leak can authorize many tables and operations. Fix: make scoped intent tokens sufficient, remove the production fallback, rotate the master key, and keep migration credentials outside the web runtime. Evidence: lib/convex/serverWriteCapability.ts:54–160.
SEC-07MediumLegacy mutations require identity, not editor role
Impact: presently dormant, but enabling Convex auth later could turn ordinary users into writers. Fix: use requireEditorWrite consistently; reserve identity-only writes for ownership-checked self-service records.
SEC-08MediumProduction-writing scripts lack enough friction · worktree remediated under #34
Current status: accepted in the current uncommitted worktree; no live write was performed. Original impact: command mistakes and workstation compromise had a large blast radius. The original evidence and recommendation remain part of the audit record until operator verification is complete.
SEC-09MediumNo central same-origin/CSRF rule for custom writes
Impact: Secure, HttpOnly, SameSite=Lax cookies are a good defense, but route security depends on browser behavior rather than an explicit server rule. Fix: enforce same-origin Origin, Sec-Fetch-Site, JSON content type, and a custom CSRF header/token for unsafe methods.
SEC-10MediumDistributed rate limiting can degrade to memory
Impact: missing/failing Redis yields a separate limit per serverless instance, and credentials login is uncovered. Fix: fail closed for sign-in/high-impact writes, key by actor and IP, alert on limiter health, and add Vercel firewall rules.
SEC-11MediumNo browser security-header baseline · worktree remediated under #49
Current status: a host-aware per-request nonce CSP and the anti-framing, MIME, referrer, and permissions baseline are implemented in the current uncommitted worktree. Database-backed SVGs retain their route-owned sandbox CSP. Remaining verification: authenticated editor loading and a real save on preview with a non-production test account, followed by deployed-response checks. No deployment or write occurred.
SEC-12Medium27 dependency advisories in the Bun lock · remediated to exception baseline under #50
Current status: production advisories fell from 4 to 1 with no High, while the full graph fell from 27 to 6. Convex/ws and affected tooling chains were upgraded. The remaining six entries reduce to three documented, owner-assigned, time-limited exception chains. Original impact: 15 high, 10 moderate, and 2 low advisories were reported; ws@8.18.0 arrived through Convex. No deployment or database write occurred.
SEC-13MediumSecret checks can copy matched secrets into logs · worktree remediated under #35
Current status: remediated for current-tree and CI scanning in the current uncommitted worktree. Checks no longer print matches and tracked file types are covered. Residual gaps: the workflow has not run from a pushed revision, full Git history and GitHub push protection remain unverified. Dependency auditing now follows the documented SEC-12 / #50 exception baseline. No tracked secret was found in the original audit.
SEC-14MediumBulk replace deletes before full validation
Impact: a bad internal import can leave a partial or empty dataset. Fix: prevalidate the full manifest and every row before deletion; fail atomically and preserve a revision for rollback.
SEC-15LowAuthenticated sign-in callback can redirect off-site
Fix: accept only same-origin, allowlisted paths—preferably /dev destinations—and reject absolute and protocol-relative URLs.
SEC-16LowPrivileged target can fall back to browser-facing URL
Fix: require an explicit server-only Convex URL and deployment identifier for privileged writes; refuse to run if either does not match.
Remediation roadmap

What I would do, in order

The first phase shrinks immediate blast radius. The second builds the durable publishing safety model.

Status note: this is the original audit roadmap. The current-status section records five accepted worktree remediations; none has been deployed.
Within 72 hours
  1. Remove analytics from admin and preview hosts.
  2. Disable production credentials or convert them to normally-off break-glass access; enforce MFA.
  3. Take and verify a Convex backup; document emergency rollback and cache purge.
  4. Rotate the broad admin key and inventory every scoped-token fallback.
  5. Make all production writers dry-run by default with deployment-bound confirmation.
Within 2 weeks
  1. Add immutable revisions, expected revision, and append-only audit events.
  2. Create draft → independent review → publish; public reads follow only the published pointer.
  3. Make expert approval a server-authenticated event by the actual approver.
  4. Protect raw/editor Convex reads and enforce citation-only invariants in Convex.
  5. Add centralized CSRF/origin/content-type rules and fail-closed distributed limits.
Within 30 days
  1. Deploy staged CSP and the browser header baseline.
  2. Patch dependencies; add Bun production audit to CI.
  3. Replace grep secret checks, pin CI actions/toolchain, and enable push protection.
  4. Run a restore drill and a false-content incident exercise.
  5. Alert on unexpected article changes, role changes, write spikes, and break-glass use.
The single most important architecture change: public pages should read an immutable published revision, not the same mutable row an editor is currently changing.

What the repository cannot tell us

  • Convex and Vercel MFA, membership, roles, and audit-log settings.
  • Backup schedule, retention, off-platform copies, and restore-test results.
  • Whether every live route uses a scoped token instead of master-key fallback.
  • Upstash health alerts and Vercel firewall/bot protection.
